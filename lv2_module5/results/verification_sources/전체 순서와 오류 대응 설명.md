# Raspberry Pi LIVE 테스트 재실행 순서

아래 명령은 라즈베리파이에 SSH로 접속한 뒤 실행한다.

## 터미널 1 — ROS 노드 실행

```bash
cd /home/pa17/git/Lv2_EYE4_Assignment/lv2_module5/ros2_ws

source /opt/ros/lyrical/setup.bash
source install/setup.bash

export ROS_DOMAIN_ID=77
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
unset ROS_LOCALHOST_ONLY

ros2 launch realsense_tracker tracker.launch.py \
  start_realsense:=true \
  start_control:=true \
  start_opencr:=true
```

실행 로그에 다음 노드가 보여야 한다.

```text
realsense2_camera_node
perception_node
control_node
opencr_node
```

## 터미널 2 — 카메라·인지·제어 확인

```bash
source /opt/ros/lyrical/setup.bash
source /home/pa17/git/Lv2_EYE4_Assignment/lv2_module5/ros2_ws/install/setup.bash

export ROS_DOMAIN_ID=77
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
unset ROS_LOCALHOST_ONLY

ros2 node list
```

`/control_node`, `/perception_node`, `/opencr_node`가 보여야 한다.

### 카메라 영상 발행 확인

```bash
ros2 topic hz /camera/camera/color/image_raw
```

약 30 Hz가 나오면 카메라 영상은 정상이다.

카메라가 인식되지 않으면 USB를 뽑고 5초 기다린 뒤 가능하면 USB 3 포트에 다시 연결한다.

### 객체 인식 확인

파란색 객체를 카메라에 보여준 상태에서 실행한다.

```bash
ros2 topic echo /target --once
```

`point.x`, `point.y`, `point.z`가 나오면 인지 노드가 정상이다.

```bash
ros2 topic echo /tracking_status --once
```

정상 추적 상태는 다음과 같다.

```text
data: TRACKING
```

### 제어 명령 확인

객체를 계속 카메라에 보여주면서 실행한다.

```bash
ros2 topic echo /control/pan_tilt_cmd --once
```

메시지가 나오고 `stop: false`이면 제어 명령이 정상 발행 중이다.

제어 노드 연결 상태는 다음 명령으로 확인할 수 있다.

```bash
ros2 node info /control_node
```

다음 항목이 있어야 한다.

```text
Subscribers:
  /target
Publishers:
  /control/pan_tilt_cmd
```

## 터미널 3 — OpenCR 상태·준비·ARM

새 터미널을 열고 다음을 실행한다.

```bash
source /opt/ros/lyrical/setup.bash
source /home/pa17/git/Lv2_EYE4_Assignment/lv2_module5/ros2_ws/install/setup.bash

export ROS_DOMAIN_ID=77
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
unset ROS_LOCALHOST_ONLY
```

OpenCR 서비스 확인:

```bash
ros2 service list | grep opencr
```

`/opencr/prepare`와 `/opencr/arm`이 보여야 한다.

### OpenCR 상태 확인 및 준비

OpenCR이 `BOOT` 상태가 아니면 먼저 OpenCR의 RESET 버튼을 한 번 누르고 2~3초 기다린다.

```bash
ros2 topic echo /opencr/bridge_status --field data --once
```

`phase`가 `BOOT`인지 확인한 뒤에만 준비 서비스를 호출한다.

```bash
ros2 service call /opencr/prepare std_srvs/srv/Trigger "{}"
```

응답이 다음과 같으면 성공이다.

```text
success=True
```

상태를 다시 확인한다.

```bash
ros2 topic echo /opencr/bridge_status --field data --once
```

`READY` 상태가 될 때까지 기다린다.

### 모터 ARM

객체가 인식되고 `/control/pan_tilt_cmd`에서 `stop: false`가 확인된 상태에서 실행한다.

```bash
ros2 service call /opencr/arm std_srvs/srv/Trigger "{}"
```

그 다음 모터가 객체를 추적한다.

## 자주 나오는 오류

### `Requires a fresh BOOT state; reset firmware first`

OpenCR을 RESET하지 않고 `/opencr/prepare`를 다시 호출한 경우다. OpenCR RESET 버튼을 누른 뒤 `BOOT`를 확인하고 다시 실행한다.

### `Requires a fresh stop=false ROS command; no automatic ARM`

아직 제어 노드가 유효한 추적 명령을 발행하지 않은 상태다. 파란 객체를 카메라에 보여주고 다음을 다시 확인한다.

```bash
ros2 topic echo /control/pan_tilt_cmd --once
```

`stop: false`가 나온 후 ARM을 호출한다.

### `/opencr/arm` 또는 `/opencr/prepare` 서비스를 찾을 수 없음

런치 터미널에 `opencr_node`가 실행됐는지 확인한다.

```bash
ros2 node list | grep opencr
ros2 service list | grep opencr
```

### 로컬 PC에서 확인하는 경우

라즈베리파이에서 노드를 실행하고, 로컬 PC에서는 다음처럼 설정한다.

```bash
source /opt/ros/lyrical/setup.bash

export ROS_DOMAIN_ID=77
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
export ROS_LOCALHOST_ONLY=0
```

로컬 PC에서는 라즈베리파이 전용 경로인 `/home/pa17/git/...`를 source하지 않는다.
